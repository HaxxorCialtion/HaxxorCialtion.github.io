MemLLM: Finetuning LLMs to Use Explicit Read-Write Memory

📄 OpenReview Link
核心观点：构造RAG数据库结构，微调LLM适配以提高benchmark score
技术架构

并非直接存储： 不是参数化记忆，而是通过LLM微调提升与一个 外部的、结构化的动态知识库 交互的benchmark scores

知识库构建： 知识库通过 三元组 (subject, relation, object) 的形式存储事实，并使用特殊标记符号（如 MEM_WRITE 和 MEM_READ ）进行操作

微调的核心作用
  • 通过微调 Mistral-7B ，让模型能够 自发判断 在生成某些关键信息之前，主动发起 MEM_READ 查询请求
  • 训练模型 在关键节点生成有效查询的决策能力 ，以及从文本中提取关系并写入知识库的能力 ( MEM_WRITE )
RAG增强 知识图谱 微调

核心创新点
1. 技能导向的任务设计

通过atomic skills构建任务间的依赖关系，使用调和平均数量化任务相关性。

2. Experience Replay机制

将历史成功轨迹作为context提供给当前任务，测试知识迁移能力。

3. Group Self-Consistency

将历史经验分组并通过投票策略聚合预测，缓解memory和推理复杂度问题。

实验结果
  • Experience Replay效果： DB环境从19%提升至78%
  • 模型差异： Qwen系列模型replay收益较小，Llama系列持续受益
  • 推理模型问题： DeepSeek-R1等推理模型容易OOM

Continual Fine-Tuning for Multilingual LLMs

📄 ArXiv Link
方法论价值：相似度度量指标和层冻结实验的参考价值
核心发现

关键观察： 当Phase 1和Phase 2数据集编码相似任务时，任务能力不退化

对比案例： • Alpaca→MultiAlpaca：任务能力保持甚至提升 • Instruct→MultiAlpaca：任务能力显著退化（0.529→0.390）
相似度量化工具（核心贡献）
DES (Dataset Embedding Similarity)
# DES(D1, D2) = ⟨E_Θ(D1), E_Θ(D2)⟩ # 使用LaBSE计算归一化平均嵌入点积 # 示例结果： # Alpaca-MultiAlpaca: 0.924 (高相似) # Alpaca-mOpenOrca: 0.792 (低相似)
MPD (Model Parameter Difference)
# MPD(Θ1, Θ2) = 1/n Σ ||w(Θ1,i) - w(Θ2,i)||_2 # 量化参数空间的表示漂移 # 越小表示模型在参数空间越接近
缓解策略对比
  • Heuristic Layer Freezing： 冻结Base→Phase1变化最大的层
  • Generative Replay： 用Phase 1模型生成对应数据，混合比例5%-10%

HippoRAG 2: From RAG to Memory

📄 GitHub Repository
创新架构：基于知识图谱和个性化PageRank的检索增强框架
核心问题与解决方案

传统RAG缺陷：

  • 意义建构不足：难以整合多个分散段落的复杂信息
  • 关联性缺失：无法发现文档间的多跳连接关系

HippoRAG解决方案： 构建更接近人类长期记忆机制的非参数学习系统

技术栈
  • 基础模型： Llama-3.3-70B-Instruct
  • 嵌入模型： NV-Embed-v2 (7B)
  • 图管理： python-igraph库
  • 核心算法： Personalized PageRank (PPR)

核心算法机制
三步过滤机制
  1. Query-to-Triple召回： 嵌入模型检索Top-5相关三元组
  2. Recognition Memory过滤： LLM判断语义相关性
  3. PPR图搜索： 基于过滤结果执行个性化PageRank
应用场景
  • 法律咨询： 法规持续更新的知识问答
  • 学术研究： 多领域文献的关联分析
  • 企业知识管理： 复杂业务流程的智能检索
  • 医疗诊断： 症状-疾病的多跳推理
技术评估

✅ 技术优势

  • 多跳推理能力强
  • 长文档理解优秀
  • 持续学习友好
  • 理论创新显著

  • 计算资源需求高
  • 处理速度较慢
  • 工程实用性存疑
  • 参数调节复杂
