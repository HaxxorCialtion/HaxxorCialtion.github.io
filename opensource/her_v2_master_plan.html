Her-v2 进化方案：构建24小时AI伴侣系统

从ASR-LLM-TTS到ASR-Agents-TTS的演进之路

项目愿景：打造一个真正的24小时AI伴侣，不仅能对话，更能理解你的生活、记住你的故事、感知你的情绪、融入你的社交网络。

🎯 核心设计哲学

拟人化的三个层次

第一层：感知拟人
不仅听到你说什么，更要理解你"怎么说"——通过多维度VAD和情感识别，感知你的语气、情绪、意图，就像一个真正在倾听的朋友。

第二层：记忆拟人
不是机械的数据库检索，而是像人类一样——有些事情记得很清楚，有些会慢慢淡忘，有些会在特定情境下突然想起。通过A-MEM系统构建互联的知识网络。

第三层：互动拟人
不是被动响应，而是主动关心——早上的问候、天气变化的提醒、察觉到你情绪低落时的安慰、甚至适时的幽默吐槽，让AI成为生活的一部分而非工具。

人机交互的终极目标

低延迟：端到端<1.5s，让对话自然流畅
高智能：通过Agents架构实现复杂任务处理
强记忆：构建用户社交网络，理解关系脉络
情感共鸣：识别并响应情绪变化
环境感知：被动监听，智能介入

🎙️ 智能VAD系统：对话触发的艺术

设计理念

核心挑战：区分"环境噪音"、"他人对话"、"用户自言自语"、"真正想与AI对话"这四种场景。

解决方案：多维度评分机制，综合判断，动态阈值。

五维评分体系

1. 静音帧检测 (权重 0.18)

非线性评分函数： - 0-300ms：0分（过滤短暂停顿） - 300-500ms：线性增长 score = (t - 300) / 200 - 500-1000ms：指数增长 score = min(1.0, exp((t - 500) / 500)) - >1000ms：1.0分（确认静音结束）

设计思路：
人类说话时会有自然的停顿（标点、呼吸），300ms以下不应触发。500ms以上的静音是句子结束的强信号，但不应立即触发，需结合其他维度。

2. 人声分贝持续性分析 (权重 0.22)

核心算法：

分贝阈值 = 基线噪音 + 15dB
持续性判断：
  - 记录最近1秒内的分贝序列
  - 计算高于阈值的占比
  - 如果占比 > 60%，则score = 1.0
  - 否则 score = 占比值

设计思路：
环境噪音（关门声、敲击声）虽然分贝高，但持续时间短。人声对话分贝会维持200-500ms以上。通过分析分贝的"持续性"而非"峰值"来区分。

动态基线校准：
每5分钟更新一次环境噪音基线，适应不同场景（办公室vs家中vs户外）。

3. SenseVoice人声概率 (权重 0.25)

技术方案：
SenseVoice自带VAD输出人声概率[0, 1]，但需要额外处理：

raw_prob = sensevoice.vad_probability(audio_frame)

# 应用置信度曲线
if raw_prob < 0.3:
    score = 0
elif raw_prob < 0.7:
    score = (raw_prob - 0.3) / 0.4 * 0.6  # 映射到[0, 0.6]
else:
    score = 0.6 + (raw_prob - 0.7) / 0.3 * 0.4  # 映射到[0.6, 1.0]

设计思路：
SenseVoice的VAD在0.3-0.7区间容易误判（音乐、电视声），需要非线性映射降低中间区间的权重。

4. 语义完整性预测 (权重 0.20)

模型选型：Qwen2-0.5B (轻量级，实时推理)

输入输出：

Input: 实时ASR转录的文本片段
Output: 句子完整概率 [0, 1]

训练数据设计： - 完整句子："今天天气真好" → 0.95 - 不完整："今天天气真" → 0.2 - 语气词结尾："那个...嗯..." → 0.1 - 疑问句："你觉得呢？" → 0.98

推理优化： - 使用vLLM加速 - 每200ms推理一次 - 缓存历史概率，平滑输出

设计思路：
单纯的VAD无法判断"我想去..."后面是否还有更多内容。通过小型LLM理解语义，判断句子是否完整，避免过早打断用户。

5. 声纹识别与社交网络 (权重 0.15)

技术方案：Phonexia Deep Embeddings / pyannote.audio

用户："Her，你觉得小王刚才说的对吗？"

家人："今天晚饭吃什么？"
→ 声纹识别：FAMILY_001(妈妈)
→ AI（温暖语气）："冰箱里还有鸡蛋和西红柿，要不做个番茄炒蛋？或者我帮你查查附近的外卖？"

VAD综合决策逻辑

加权求和：

def calculate_vad_score(audio_stream):
    scores = {
        'silence': silence_detection(audio_stream),      # 0.18
        'volume': volume_persistence(audio_stream),       # 0.22
        'human_voice': sensevoice_vad(audio_stream),     # 0.25
        'completeness': semantic_completion(text),        # 0.20
        'speaker': speaker_identification(audio_stream)   # 0.15
    }

    weighted_score = (
        0.18 * scores['silence'] +
        0.22 * scores['volume'] +
        0.25 * scores['human_voice'] +
        0.20 * scores['completeness'] +
        0.15 * scores['speaker']
    )

    # 动态阈值
    threshold = 0.75
    if weighted_score > threshold:
        return "TRIGGER_CONVERSATION"
    elif weighted_score > 0.45:
        return "CONTINUE_LISTENING"  # 可能还没说完
    else:
        return "IGNORE"  # 环境噪音

特殊规则： 1. 用户主动唤醒：任何维度得分无效，直接触发 2. 情绪波动检测：如果情感识别检测到明显的负面情绪（愤怒、悲伤），降低阈值到0.6 3. 时间上下文：深夜（23:00-6:00）提高阈值到0.85，避免误触发

指标 目标值 说明

🧠 Agents架构：从单一LLM到智能群体

Master Agent：总协调者

职责： - 理解用户意图 - 分配任务给各个Sub-Agent - 整合各Agent的输出 - 决策是否调用外部API

模型选型： - 本地：Qwen2.5-7B-Instruct（快速响应） - 云端：Claude-3.5-Sonnet / GPT-4（复杂推理）

决策树：

用户输入 → Master Agent分析

├─ 简单闲聊 → Dialog Agent → 直接响应
├─ 查询历史 → Memory Agent → 检索记忆 → Dialog Agent整合
├─ 情感支持 → Emotion Agent → 分析情绪 → Dialog Agent共情回应
├─ 复杂任务 → Tool Agent → 调用工具/API → 返回结果
└─ 多步推理 → 云端LLM（Claude/GPT-4）→ 深度分析

Sub-Agents生态

Memory Agent：记忆管家

核心技术：A-MEM（Agentic Memory）+ Mem0

职责： 1. 写入记忆： - 自动提取对话中的关键信息 - 生成结构化记忆节点（时间、地点、人物、情感、标签） - 建立记忆之间的关联链接

  1. 检索记忆：
  2. 向量相似度搜索（ChromaDB）
  3. 图关系查询（Neo4j）

  4. 元数据过滤（时间范围、人物、地点）

  5. 记忆演化：

  6. 重要性衰减（时间越久权重越低）
  7. 关联强化（频繁提及的记忆权重提升）
  8. 主动遗忘（低价值记忆定期清理）

A-MEM的动态链接机制：

当新记忆写入时： 1. 计算与历史记忆的相似度（Embedding） 2. 提取共同实体（NER） 3. 分析时序关系（前因后果） 4. 建立双向链接（top-5相关记忆）

示例：

新记忆："明天要去机场接妈妈"
↓
自动链接：
  → "妈妈下个月生日"（人物关联）
  → "上次去首都机场"（地点关联）

三维评分机制：

def calculate_retrieval_score(memory, query, current_time):
    # 1. 时间衰减（Recency）
    hours_since = (current_time - memory.timestamp).hours
    recency_score = 0.995 ** hours_since

    # 2. 重要性（Importance）
    importance_score = memory.importance

    # 3. 相关性（Relevance）
    query_embedding = embed(query)
    relevance_score = cosine_similarity(query_embedding, memory.embedding)

    # 加权求和
    final_score = (
        0.3 * recency_score +
        0.3 * importance_score +
        0.4 * relevance_score
    )

    # 访问热度加成
    if memory.access_count > 10:
        final_score *= 1.1

    return final_score

def calculate_importance(memory_content):
    # LLM评分Prompt

    记忆内容：{memory_content}

    评分标准：
    - 涉及重要事件（生日、纪念日、关键决策）→ 0.9-1.0

    - 日常对话、天气询问 → 0.2-0.4
    - 闲聊、无意义内容 → 0.0-0.2

    """

    score = llm.generate(prompt)

用户控制

一键清除：

设置 → 隐私 → 清除所有记忆
→ 确认后删除ChromaDB、Neo4j、PostgreSQL中的所有用户数据

选择性遗忘：

用户："忘记我刚才说的那件事"
→ AI识别"刚才"的时间范围
→ 删除对应记忆节点及其链接
→ "好的，已经忘记了。"

隐私模式：

场景：公共场合开会
用户："进入隐私模式"
→ 停止被动监听
→ 停止主动关怀
→ 所有对话不记录
→ 通知栏显示"隐私模式"

伦理边界

不做什么： 1. 不监控：被动监听仅用于记忆，不用于监控用户行为 2. 不出售数据：任何用户数据不出售给第三方 3. 不过度依赖：定期提醒用户"我只是AI，重要决策请咨询专业人士" 4. 不替代人际关系：检测到用户过度依赖时，鼓励真实社交

💡 创新亮点

1. 五维混合VAD决策

业界首创：结合静音、分贝持续性、人声概率、语义完整性、声纹识别五个维度，实现智能对话触发，误触发率<5%。

技术突破：动态阈值调整，适配不同环境（办公室/家中/户外），解决"过度敏感"vs"反应迟钝"的平衡问题。

2. 社交网络式声纹管理

创新点：不是简单的"多用户识别"，而是围绕核心用户构建社交图谱（家人-朋友-同事-陌生人），实现： - 根据说话人调整回应策略 - 隐私分级保护（陌生人面前隐藏敏感信息） - 社交记忆管理（记住每个人的生日、喜好）

应用场景：多人对话理解、情境适配、记忆归因

3. A-MEM动态知识网络

核心理念：记忆不是死板的数据库，而是像人类大脑一样的"知识网络"，新记忆会触发旧记忆的更新和演化。

技术方案：基于Zettelkasten方法，每条记忆都是独立的"卡片"，通过语义、实体、时序建立多维链接，实现： - 联想记忆（"妈妈生日" → 想起"送礼物"） - 因果推理（"辞职创业" → 追溯"工作瓶颈"） - 记忆衰减（时间久远的记忆逐渐模糊）

4. 情感驱动的拟人化交互

设计哲学：AI不应该是冷冰冰的工具，而应该是有温度的伙伴。

实现方式： - 实时情感识别（SenseVoice） - TTS情感控制（语速、音调、停顿） - 主动关怀触发器（定时问候、情绪察觉） - 非语言声音插入（笑声、叹息、思考） - 适度的"不完美"（偶尔说"我不确定"）

5. 环境感知的被动监听

创新点：AI不仅在"对话"时工作，更在"沉默"时学习。

核心功能： - 24小时被动监听（低功耗VAD） - 智能过滤（哪些对话值得记忆） - 情境捕获（工作/休息/社交场景） - 隐私保护（本地处理，不上传音频）

应用场景： - 自动记录重要信息（"明天记得带伞"） - 理解用户日常习惯（每天7:30吃早餐） - 情绪变化追踪（连续三天情绪低落）

6. 本地+云端混合架构

优势： - 本地LLM：低延迟、隐私保护、离线可用 - 云端API：复杂推理、知识检索、工具调用

智能路由：Master Agent自动判断任务复杂度，决定本地处理还是云端调用。

🚨 风险与挑战

技术风险

1. VAD误判风险
风险：环境噪音（电视、音乐、他人对话）导致频繁误触发
缓解：多维度评分+动态阈值，持续训练优化

2. 记忆检索延迟
风险：随着记忆量增长，检索变慢影响响应
缓解：分层存储（热/冷数据）、索引优化、缓存机制

3. 本地LLM能力限制
风险：Qwen2.5-7B在复杂推理任务上不足
缓解：智能路由到云端API（Claude/GPT-4）

用户体验风险

1. 过度拟人化的"恐怖谷"效应
风险：AI太像人但又不完全是人，导致用户不适
缓解：适度的"不完美"，偶尔承认"我是AI"

2. 隐私担忧
风险：24小时监听引发用户对隐私的担忧
缓解：透明化数据处理流程、本地优先、用户控制

3. 过度依赖
风险：用户过度依赖AI，影响真实社交
缓解：定期提醒、鼓励真实社交、检测过度使用

资源风险

1. GPU显存不足
风险：多模型同时运行导致OOM
缓解：模型量化（int8/int4）、模型卸载、双卡部署

2. Android电量消耗
风险：后台持续运行耗电快
缓解：低功耗VAD、智能暂停、降采样
